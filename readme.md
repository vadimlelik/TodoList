Давайте разберем как работает this в классах и почему мы не теряем контекст в нашем случае:

this в классах:
В классах this указывает на экземпляр класса
Когда мы создаем новый экземпляр через new TodoList(), this внутри конструктора и методов класса будет указывать на этот конкретный экземпляр
Через this мы получаем доступ ко всем свойствам и методам класса
Почему мы не теряем контекст в этой строке:

deleteButton.addEventListener('click', () => this.deleteTodo(todo.id))
Здесь используется стрелочная функция () =>, и это ключевой момент! Давайте сравним два способа:

Code
CopyInsert
// Способ 1: Стрелочная функция (работает правильно)
deleteButton.addEventListener('click', () => this.deleteTodo(todo.id))

// Способ 2: Обычная функция (потеряет контекст)
deleteButton.addEventListener('click', function() {
this.deleteTodo(todo.id) // this будет указывать на кнопку, а не на класс!
})
Почему так происходит:

Стрелочные функции (=>):
Не создают свой собственный контекст this
Наследуют this из внешнего окружения (лексического контекста)
В нашем случае this берётся из метода renderTodos, где он указывает на экземпляр класса
Обычные функции:
Создают свой собственный контекст this
При использовании как callback, this будет указывать на элемент, который вызвал событие
В случае с событием клика, this будет указывать на кнопку
Поэтому мы используем стрелочную функцию () =>, чтобы сохранить правильный контекст this и иметь доступ к методам класса.

Пример для лучшего понимания:

Code
CopyInsert
class TodoList {
constructor() {
this.name = "My TodoList";
}

    // Метод с использованием стрелочной функции
    correctWay() {
        const button = document.createElement('button');
        button.addEventListener('click', () => {
            console.log(this.name); // Выведет "My TodoList"
        });
    }

    // Метод с использованием обычной функции
    wrongWay() {
        const button = document.createElement('button');
        button.addEventListener('click', function() {
            console.log(this.name); // Выведет undefined
        });
    }

}
В этом и заключается причина, почему мы используем стрелочную функцию в обработчике события - чтобы сохранить доступ к методам и свойствам нашего класса через this.
